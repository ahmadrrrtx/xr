## Design decisions
1. **One canonical list store: `stores/runsStore.ts`.** brainStore keeps spans/streams; runsStore keeps `RunSummary` for every run (seed + live). Bridge = `useBrainStore.subscribe()` diffing `runs` → `runsStore.upsertFromBrain()` (gives honest live token/cost ticks with zero changes to the stream seam) **plus** Tauri listeners for `brain:run-update` / `run:cancelled` (cross-window; in-window duplicates are idempotent upserts).
2. **Runs → Brain consistency:** `brainStore.loadRun` consults `runsStore` when an id isn't persisted: metadata (title/agent/model/status/times/tokens/cost/shortId) comes from the summary, the trace is the deterministic script for that id's flavor (seed ids embed a flavor suffix so failed runs open as the error trace).
3. **Seed = finished runs only.** No fake "running"/"waiting" rows (Design law 2: status must reflect real state). Live rows come from real mock streams: Brain "Start a demo run", the Runs header's "Demo run" button/empty state, chat tool calls, cmdk. `mock-waiting` stays Brain's canned demo and is not seeded.
4. **Seed determinism:** fixed RNG seed; times are offsets inside calendar days (today = within the elapsed part of the day), so counts per day/hour and all ids/titles/costs are stable across reloads; absolute timestamps follow the calendar. ~64 runs over 30 days, heavier in the last 48 h; mix of cloud ($) and local ($0) models.
5. **Ticking without churn:** store holds a `clock` (updated every 500 ms while anything is in progress, 2 s when off-screen). Running rows derive `duration = clock − startedAt`; tokens/cost arrive via the bridge. The sorted/filtered id list recomputes on structural change (add/remove/status/filter/sort/search); while sorting by a live column it also refreshes at most once per second.
6. **STOP ALL / kill semantics:** "in progress" = running + waiting. `kill(id)`: brainStore stream owner → `stopRun(id)` (withdraws the approval, kills the stream) → bridge; non-owned → mark killed locally; always `invoke('cancel_run')` (Rust re-broadcasts `run:cancelled` to every window). Confirmation is a Radix AlertDialog (role alertdialog) with an optional reason.
7. **Charts hand-rolled SVG** (bar / stacked area / donut), ~1 file; sr-only tables; draw animations gated by reduced motion. Data reflects the current filter+search+date range (donut/area), runs-per-hour always last 24 h of the filtered set.
8. **Export** honours filter+search+range; CSV columns = Status, ID, Title, Agent, Workspace, Model, Started (ISO), Ended (ISO), Duration ms, Tokens In, Tokens Out, Cost USD, Error summary. Native save dialog in Tauri, Blob download in the browser.
9. **Nav label** "Control Room", icon `Activity` (1.5 px). Topbar title follows NAV_ITEMS automatically.
10. **Query params:** `/runs?status=running|failed|…` and `/runs?action=stop-all` (palette/HUD-safe intent).

## Risks
- Running rows re-render ~10×/s per live run (token ticks) — rows are memoised and keyed; the virtualised list only mounts ~30.
- `react-window` v2 `rowKey` + AnimatePresence don't mix (rows are absolutely positioned) → new-row flash is a CSS keyframe on the inner cell, triggered by a `firstSeen` set (tree.tsx pattern).
- Sorting 10k rows on every structural change ≈ 5–10 ms — fine; stress seed is dev-only.

## Build log — what changed against the plan
- **Seed:** 60 finished runs over 30 days (`RUNS_PER_DAY` weights, heavier last 48 h); canned Brain ids keep their placeholder shortIds (#847 medium, #303 error, #512 long, #101 short, #900 stress). Live demo ids start at `mock-latest-848` (`demoCounter = 847`), so the first demo row is "#848".
- **Chat tool calls stream live:** `chatStore` `tool_call` → `startMockRun(summary, {flavor:'short'})` when nothing is live. `brainStore.loadRun` treated only `flavor === 'latest'` as live; `mock-latest-N-short` fell into the frozen-snapshot branch, so the row never ticked. Fixed: live branch = `flavor === 'latest' || id.startsWith('mock-latest-')`.
- **Started column:** relative ("just now", "14m ago") inside the hour, clock ("08:15") for today, "Yesterday 21:…" / "Sep 21 …" before; full timestamp in `title`. Column widened to 104 px.
- **Stats bar** always shows today's global numbers (not the filtered view); cost tile prints `$0` when there is no spend.
- **Keyboard:** `C` toggles charts (plan said "charts chip only"); `R` reseeds in the browser seam ("Refreshed").
- **Export in Tauri** goes through Rust `save_runs_export(filename, contents) -> Option<String>` (native save dialog + fs write); browser seam uses Blob + `<a download>`.
- **Rust** (`commands/runs.rs`): `list_runs` (empty — renderer-owned until Phase 14 runtime), `cancel_run(id, reason?) -> Result<(), String>`, `bulk_cancel_runs(ids, reason?) -> usize`; both emit `run:cancelled { ids, reason, at }` to every window. Compile-checked by CI only (no cargo in the sandbox).
- **Lint fixes after the first `bun run lint`:** no setState-in-effect (`StopDialog` reason field remounts via `key`; `useTween` moved to `screens/Runs/useTween.ts` and returns the target directly under reduced motion), donut arc offsets precomputed (no render-time mutation), `WorkspaceLanding` uses the store `clock` instead of `Date.now()` in render.
- **Second verification pass (before push):** added the optional `⌘⌥R` → `/runs` chord (`SHORTCUTS` row `control-room`, so it shows up in Settings → Shortcuts and is rebindable; `settings-core.test.ts` counts updated 9→10 / 6→7); the Runs key handler now yields to ANY open layer (approval modal — a demo run's approval span raises it app-wide and the row shows `waiting` — palette, settings dialogs), not just its own stop dialog; `archive()` refuses in-progress runs ("Run #850 is still in progress · Stop it first…", menu item disabled while live) so a live agent can never vanish from the Control Room; the `E` hint in the Export menu now sits on the CSV item (that is what `E` does).
