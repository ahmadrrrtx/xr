## 4. In-scope changes

Six work items. §4.1 is owner-blocked; the rest are yours.

### 4.1 Versioned consent record *(mechanism only — text is owner-supplied)*

Replace the ephemeral `understood` boolean with a durable record:

```ts
interface ConsentRecord {
  docVersion: string;        // from the supplied document, not invented
  acceptedAt: number;        // epoch ms, set at the moment of acceptance
  surfaceScope: string[];    // which surfaces the acceptance covers
}
```

Rules:
- Persist through the existing `persistent-store` (same mechanism as
  `ONBOARDING_KEY`); **one** record, versioned — not a second parallel key.
- Refusing acceptance **blocks completion** and blocks advancing past the consent step.
  This is a hard gate, not a warning.
- **Changing `docVersion` must force re-acceptance.** The record is compared against the
  current document version on every launch; a mismatch sets `needsReacceptance` and blocks
  completion until accepted. Tested both ways.
- The consent screen must be **re-openable from Settings** without re-running the wizard,
  and must show the accepted `docVersion` + human-readable `acceptedAt`.
- Do **not** invent the document. `docs/privacy/**` receives the owner's text (D-004).
  Until it exists, use the guarded placeholder described in §0.
- **Consent precedes consequence** (`MASTER_PLAN.md` §F `XR-P02` item 10): no key write,
  no download, no provider call may occur before the record exists.

### 4.2 Resumable per-step checkpoint (D-009)

- Persist `{ step, docVersionSeen, choices }` on every advance. On relaunch, resume at the
  recorded step — **never at 1** — and re-render it with its prior choices intact.
- D-009 is explicit: **per-step checkpoint only.** A mid-download interruption restarts the
  download with a clear message; do **not** attempt partial-blob resumption (Ollama owns
  that semantic, and owning it is out of scope).
- **Durable migration, additive** (`MASTER_PLAN.md` §F `XR-P02` item 14): an existing
  `onboardingComplete === true` must map to "complete at current doc version = **unknown**"
  and prompt **once** — never re-run the whole wizard. Rollback = ignore the new record and
  keep reading the boolean. Test the migration from a pre-existing boolean store.
- The checkpoint is committed **only** after a step's own success predicate, never on
  render.

### 4.3 Per-step error boundary

- Wrap **each** step in an `ErrorBoundary` that renders a recoverable card (title, what
  failed, *Retry this step*, *Back*) and keeps the wizard alive. A throwing step must not
  blank the window — that is `AUD-001` cause (c), the failure the audit calls out.
- The boundary is per-step, not one boundary around the wizard: one bad step must not hide
  the others, and the failure must name the step.
- No `null` render path may remain (`OnboardingScreen.tsx:26,48`; `StepDownload.tsx:182`).
  Replace each with a real starting surface that says what it is doing.

### 4.4 The completion predicate and the limited mode *(XRD-004)*

Completion becomes a **named, testable predicate**, not the absence of errors:

```
canComplete = engineUsable && (providerConfigured || limitedModeConsciouslyChosen)
```

- `engineUsable` is `isEngineUsable(engineStore.status)` from `XR-P01` — `ready` or
  `degraded`. Consume it; do not reimplement.
- `providerConfigured` is an **observed** engine acknowledgement (the existing
  `setEngineDefault` success), never "the user tapped a tile".
- `limitedModeConsciouslyChosen` requires an explicit user action with copy that states
  **what XR cannot do** in that mode. Guest mode already exists
  (`StepModelSetup.tsx:167-169` "Continue as guest") — reuse it, and make the resulting
  screen say plainly that chat needs a provider. A default/no-input must **not** count as
  conscious.
- An unhealthy engine can never reach `complete`. A healthy engine with no provider can
  reach it **only** through the limited-mode choice.
- Both directions are tests (§4.7).

### 4.5 Voice preview honesty (D-010, XRD-011)

The defect is the **substitution**, not the browser API. Because an engine TTS path exists
(`POST /api/voice/say`), implement option **(a)** as the primary:

- Preview through the engine for the `piper-*` voice the user has selected, so the user
  hears the voice that will actually be used. If the engine cannot synthesise yet (no
  weights downloaded), fall back to Web Speech **only with the explicit label**:
  *"Approximation — the configured voice is synthesised by XR's engine on this device."*
- The fallback must be **visible**, not silent, and must have a working failure state
  (if playback fails, say so and offer the honest alternative).
- Assert in a test that the preview path is **either** engine-voiced **or** explicitly
  labelled. There must be no third branch.

### 4.6 Settings surfaces

- A consent card showing `docVersion` + `acceptedAt`, with a re-open action.
- A data-flow notice stating plainly that **cloud providers receive whatever prompt and
  context is sent to them** (D-004's required minimum). Same owner-text dependency as §4.1.

### 4.7 Tests — `test/desktop/onboarding-state.test.ts` (new file)

| # | Test | Asserts |
|---|---|---|
| 1 | Consent refused | completion blocked; cannot advance past the consent step |
| 2 | Consent accepted | a versioned record persists with `acceptedAt` + `surfaceScope` |
| 3 | Doc version bump | forces `needsReacceptance`; completion blocked until re-accepted |
| 4 | Migration | a legacy `onboardingComplete=true` ⇒ prompts **once**, never restarts the wizard |
| 5 | Resume | a crash between step N and N+1 resumes at **N**, choices intact |
| 6 | Download restart | an interrupted download restarts with a message (D-009), no partial-blob logic |
| 7 | Boundary | a step that throws renders the recoverable card; the wizard stays alive |
| 8 | Predicate — negative | unhealthy engine ⇒ **cannot** complete |
| 9 | Predicate — positive | healthy engine + configured provider ⇒ completes |
| 10 | Predicate — limited mode | healthy engine + explicit limited mode ⇒ completes **and** the result says what is unavailable; a default choice does **not** complete |
| 11 | Voice honesty | preview is engine-voiced **or** explicitly labelled; no third branch |
| 12 | No `null` renders | no `return null` path remains in the wizard's step components |

All offline and deterministic. No sleeps, no network, no timers beyond a few ms.
